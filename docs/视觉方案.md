# 视觉方案稿（v1，可评审）

**状态**：方案稿。本文只描述目标视觉，**不代表已实现**；`apps/web` 目前仍是 Excalidraw 默认外观 + 临时内联样式外壳，按本文落地是后续独立任务。

**主色**：干玫瑰 `#A85C7C`（开发文档 §9 已定）。

**适用范围**：自有外壳（入口页、白板面板、画布页顶栏与分享面板、登录/注册页、认领对话框）。
**不适用范围**：画布内部的元素渲染、库自带工具条与属性面板——边界与分工见 §5。

**与开发文档 §9 的关系**：本文是 §9 的可执行细化，不是替代。色值、圆角、阴影、4px 栅格、动效时长全部沿用；**另有三处修正**（见附录 B），原因是实测对比度未达 §9 的文字描述，以及库的色板不可替换。

### 1.3 语义色

每种语义色给三个值：`bg`（区块底）、`border`（描边）、`text`（文字/图标）。**文字一律用 text，不用主色值本身**。

| 语义 | bg | border | text | dot/填充 | 对比度（text / 白） |
|---|---|---|---|---|---|
| 成功 | `#EAF3EF` | `#CFE3DA` | `#2F6B57` | `#8FB8A8` | 6.25:1 |
| 警告 | `#FBF1E4` | `#EBD8BE` | `#8A5E22` | `#C69257` | 5.67:1 |
| 危险 | `#FBEAEA` | `#EFD2D2` | `#9E4A4A` | `#B96B6B` | 5.95:1 |
| 信息 | `#EDF1F7` | `#D6DFEC` | `#3F5B7A` | `#8FA3BF` | 7.03:1 |

说明：
- `#8FB8A8` / `#C69257` / `#B96B6B` / `#8FA3BF` 是**填充色**（圆点、进度条、图标底），单独当文字用在白底只有 2.6–3.9:1，不达标。
- 危险按钮（实心）用 `#9E4A4A` 底 + 白字（5.95:1）；用 `#B96B6B` 底 + 白字只有 3.90:1，**不合格**。
- 语义色不参与品牌表达：成功态不要用玫瑰色，"保存成功"的绿点就用 `#8FB8A8`。

### 1.4 画布与纸张

| 角色 | Hex | 说明 |
|---|---|---|
| 画布视口底 | `#FFFFFF` | **必须中性**。给画布铺米色/粉色会让用户画的白、灰、黄全部偏色，也会让导出的图与屏上不一致。落地对应 Excalidraw `appState.viewBackgroundColor` |
| 画布网格 | `#EDE4E8`，opacity .5 | 默认关闭；开启时线宽 1px |
| 页面底 | `#FBF7F9` | 画布外所有区域 |
| 纸张（卡片/文档块） | `#FFFFFF` + 1px `#EFE4E8` | 不用 `#FCFCFC` 等中间灰，避免与 `bg` 混成"脏底" |
| 深色模式画布 | `#1E1A1D` | v1 不做；变量预留 |

**画布与外壳的衔接**：画布是"纸"，外壳是"桌面"。两者接触处只允许 1px `#EFE4E8` 或 8px 的 `bg` 间距，**不允许粉色渐变过渡或粉色描边包围画布**，否则画布里的玫瑰色元素会和外壳混成一片，用户分不清哪是内容哪是界面。

### 1.6 禁止使用的组合

以下每条都是上表演算的直接结论，落地时按此 review：

1. **主按钮 hover 不能变浅。** 白字放 `rose-500` `#C07E97` 只有 3.15:1。hover 必须**变深**到 `#8E4568`（6.56:1），按下到 `#743551`（8.86:1）。这推翻了 §9 里"500 用于 hover"的写法（见附录 B-1）。
2. **不能用 `rose-100` 文字压主色底。** `#F4E3E9` on `#A85C7C` = 3.79:1，比白字更差。
3. **主色不能做页面底上的正文、说明、时间戳、小字链接。** `#A85C7C` on `#FBF7F9` = 4.41:1。这类文字统一 `#8E4568`。
4. **主色不做大面积铺底。** 除单个按钮、单条提示条、单个激活标签外，主色填充面积不超过视口 5%；否则与中性元素对比失衡，整页"发粉"。
5. **标签底（`rose-100`）上不放主色文字。** 3.79:1。标签文字用 `#8E4568`（5.31:1）或 `#3A2E33`（10.51:1）。
6. **`#9A8A90` 不能做时间戳。** 3.08:1。时间戳、协作者名副行、字段说明一律 `#6B5A61`；只有输入框 placeholder 和禁用态可用 `#9A8A90`。
7. **实心危险按钮不用 `#B96B6B`。** 白字 3.90:1。
8. **白字不能加透明度。** 主色上 80% 不透明度白字约 3.5:1，视觉上"发灰"且不达标；主按钮禁用态改用 `#E2D6DB` 底 + `#7E6C73` 文字（4.5:1 级别），而不是降低不透明度。
9. **画布内不使用主色描边、主色选中框以外的主色装饰。** 画布内的颜色主权在用户内容（见 §5.4）。
10. **不用纯黑 `#000` 做文字或阴影底座。** 用 `#3A2E33` / `rgba(58,46,51,x)`。
11. **不把状态只交给颜色。** 在线/离线、可编辑/只读、保存中/已保存，都必须有文案或图标差异（WCAG 1.4.1）。
12. **毛玻璃底上不放正文。** `backdrop-filter` 的实际背景不可预测，对比度无法保证；需要模糊的场景一律改为不透明底（见 §6.2）。

## 2. 字体与排版

### 2.1 字体栈（Windows / macOS 都要能看）

设计取舍：**拉丁字形用 Inter 拿排印质感，中文字形走系统字体保证零加载风险**。Inter 不含汉字，天然落到后面的中文字体，不需要 `unicode-range` 拆分。

| 用途 | 字体栈 |
|---|---|
| UI / 正文（`--font-sans`） | `"Inter", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI", "Microsoft YaHei", "Source Han Sans SC", "Noto Sans SC", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Arial, sans-serif` |
| 展示标题（`--font-display`） | `"Fraunces", "Source Han Serif SC", "Noto Serif SC", "Songti SC", "SimSun", Georgia, serif` |
| 代码 / 链接 / boardId（`--font-mono`） | `"Cascadia Mono", "SF Mono", "JetBrains Mono", Menlo, Consolas, "Liberation Mono", monospace` |

逐段说明（这是这份字体栈成立的原因，评审时不必再改顺序）：

| 段 | 覆盖对象 | 备注 |
|---|---|---|
| `Inter` | 拉丁字母、数字 | 需自托管（见下）；未加载时无缝落到系统拉丁 |
| `PingFang SC` | macOS 10.11+ / iOS 中文 | mac 首选，字形现代、字重齐 |
| `Hiragino Sans GB` | 较老 macOS | `PingFang SC` 缺字时兜底 |
| `Microsoft YaHei UI` / `Microsoft YaHei` | Windows 8.1+ / Windows 7+ | **Windows 没有苹方**，这两项决定 Windows 上的中文观感；雅黑只有 400/700 两档，500 会被合成，见 §2.3 |
| `Source Han Sans SC` / `Noto Sans SC` | Linux、Docker 内截图、缺失前两者的环境 | 保证 CI 截图与开发机一致 |
| `-apple-system` / `Segoe UI` / `Roboto` / `Arial` | 拉丁兜底 | Inter 未加载时的退路 |

`--font-display` 的使用约束：
- **只在 ≥20px 使用**。Windows 的宋体（`SimSun`）在 12–16px 发虚、笔画粘连，不能用于正文或小标题。
- 自托管 `Fraunces`（拉丁，600，`woff2`，只含 Latin-1 + 标点，约 28KB）与 `Noto Serif SC` 子集（只含标题用到的常用字，控制在 200KB 内）都是**可选增强**：`font-display: swap`，加载失败自动退回无衬线 600。
- 若评审决定"零自托管字体"（离线演示、内网部署更稳），把 `--font-display` 直接改成 `--font-sans` + `font-weight: 600`，视觉损失可接受。

`--font-mono` 的使用约束：分享链接、`boardId`（12 位）、`opId`、时间戳里的毫秒、快捷键。**中文不进 mono**（等宽中文字体缺字会掉到系统字体，出现基线跳变）。

### 2.2 字号阶梯（6 级）

以 12 为最小、28 为最大，避免 11px 这类"看着精致、实际难读"的值。

| Token | px / line-height | 字重 | 字距 | 用途 |
|---|---|---|---|---|
| `micro` | 12 / 18 | 500 | 拉丁 +0.01em | 时间戳、徽标、缩放比、快捷键、链接使用次数 |
| `caption` | 13 / 20 | 400 | 0 | 辅助说明、表单提示、协作者名、字段 label |
| `body` | 14 / 22 | 400 | 0 | 默认正文、表格内容 |
| `body-strong` | 14 / 22 | 500 | 0 | 按钮文字、列表标题、表格首列 |
| `subtitle` | 16 / 24 | 600 | 0 | 区块标题、对话框小标题、输入框内大文本 |
| `title` | 20 / 30 | 600 | 0 | 对话框标题、空态标题、卡片区标题 |
| `display` | 28 / 40 | 600 | 拉丁 −0.01em | 页面主标题（面板页、入口页 H1） |

补充规则：
- **移动端标题降一档**：`display` → `title`，`title` → `subtitle`；正文与辅助文字**不降**（12px 在手机上已是可读下限）。
- 字重只用 400 / 500 / 600；**700 仅用于指标数字**（元素数、在线人数、进度百分比），且必须是 `tabular-nums`。
- 中文一律不加字距；拉丁小标题 +0.02em；全大写拉丁标签（"READ ONLY" 不用，中文界面不用全大写）+0.08em。
- 段落行高 1.7，UI 单行行高 1.5；同一段文字不混用行高。

### 2.3 四类用法与实际场景

**标题（display / title / subtitle，一律 600）**
- 入口页 H1："打开就能画。"
- 面板页 H1："我的白板" + 右侧元素计数（12/500 `#6B5A61`）。
- 画布页标题：不用 H1 尺寸，用 `body-strong`（见下），因为画布才是主角，标题不该抢视觉。
- 对话框标题："分享这块白板"、"把这 2 块临时白板转到你的账号？"（`title` 20/30，超长换行不用省略号）。

**正文（body / body-strong）**
- 卡片正文、表单、说明段落：`body` 14/22 `#3A2E33`；段落最大宽度 68ch（面板内约 560–640px），超过换行不撑满。
- 按钮：`body-strong` 14/22，**行高收到 20**（按钮高度由固定 40/44 控制，不靠 padding 撑）。
- 板列表标题：`body-strong` 14/22 `#3A2E33`，单行 ellipsis，`title` 属性给全名；hover 时文字变 `#8E4568` 并显示下划线（颜色不是唯一变化）。

**辅助文字（caption / micro）**
- 时间戳：`micro` 12/18 **`#6B5A61`** + `tabular-nums`，文案"3 分钟前"；>7 天显示 `10-28`，`title` 给完整时间。**不用 `#9A8A90`**（3.08:1）。
- 协作者名：`caption` 13/20 500 `#3A2E33`，最多 6 字截断，hover 出全名气泡；游客名"访客 7f3a"用 `#6B5A61` + 12px 角标。
- 字段说明 / 错误提示：`caption`，正常 `#6B5A61`，错误 `#9E4A4A`。
- 徽标（`TempBadge` / 只读）：`micro` 12/18 500–600，高 20–24，`radius 999`。

**代码 / 数字（mono + tabular-nums）**
- 分享链接：`mono` 12/18 `#3A2E33`，允许 `word-break: break-all`，容器底 `#F4EEF1`，`radius 6`。
- `boardId` / `opId`：`mono` 12/18 `#6B5A61`，字距 +0.02em 提高辨识。
- 缩放比（"100%"）、元素计数、在线人数：`micro` 12/18 500 `#6B5A61` `tabular-nums`；指标数字用 28/36 700 `#3A2E33` `tabular-nums`。
- 不使用等宽字体排中文。

**Windows 上的字重陷阱**：`Microsoft YaHei` 只有 Regular/Bold，500 会被浏览器合成（视觉接近 400），600 也会被合成（视觉接近 700）。因此：
- 中文层级差异优先靠**字号 + 颜色**建立，不靠 400/500 的细微差异；
- 需要"加粗感"的中文标题直接用 600，别用 500；
- 拉丁（Inter 有真 500/600）可以正常用 500。

## 3. 形状与节奏

### 3.1 圆角

| Token | 值 | 用途 |
|---|---|---|
| `radius-sm` | 6px | 标签、代码块、输入框内的小元素、缩略图占位 |
| `radius-md` | 10px | 按钮、菜单项、输入框、提示条 |
| `radius-lg` | 14px | 卡片、浮动工具条容器、toast |
| `radius-xl` | 20px | 对话框、分享抽屉、移动端底部抽屉顶部 |
| `radius-pill` | 999px | 头像、状态胶囊、只读徽标 |

规则：
- 上限 20px。**不用 24px 全圆角**——24px + 厚投影是消费级 App 语言，会把工具感洗掉（§9.6 已定）。
- 嵌套圆角 = 外层 − 内边距，最小 6px（20 里面嵌 16 + 4 内边距 = 圆角 10，不出现"胶囊套胶囊"）。
- 画布元素圆角由库控制，**外壳不覆盖**。

### 3.2 边框与描边

| 角色 | 值 | 说明 |
|---|---|---|
| 分隔线 | 1px `#EFE4E8` | 纯装饰，1.24:1；不能作为控件的唯一边界 |
| 卡片描边 | 1px `#EFE4E8` | 白底卡片放在 `#FBF7F9` 上，靠底色差 + 细线，不靠重投影 |
| 控件边界（输入框、可点块） | 1px `#A08D95`（3.12:1）或 `#C07E97`（3.15:1） | 满足 WCAG 1.4.11 的 3:1；输入框默认 `#A08D95`，选中/激活用 `#C07E97` |
| 焦点环 | 2px `#A85C7C` + 2px offset（`#FFFFFF` 内衬） | 4.68:1，键盘可见性达标；**不用 outline: none** |
| 图标线宽 | 1.5px（1x）/ 2px（2x 屏） | 见 §9.7 |
| 错误态描边 | 1px `#9E4A4A` | 同时必须给文字提示与图标，不只换色 |

不使用 3px 以上的边框；不用双色描边；不用渐变描边。

### 3.3 阴影（具体值）

沿用 §9，全部以暖灰 `rgba(58,46,51,·)` 为基色，不用纯黑。

| Token | 值 | 用途 |
|---|---|---|
| `shadow-0` | `none` | 列表卡片默认态、表格行 |
| `shadow-1` | `0 1px 2px rgba(58,46,51,.06)` | 输入框内阴影、贴地卡片、头像 |
| `shadow-2` | `0 6px 18px rgba(58,46,51,.08)` | 卡片 hover、浮动工具条、登录卡片 |
| `shadow-3` | `0 16px 40px rgba(58,46,51,.12)` | 对话框、分享抽屉、下拉菜单（**同一屏最多 1 个**） |
| `shadow-focus` | `0 0 0 2px #FFFFFF, 0 0 0 4px #A85C7C` | 焦点环（替代 `outline`，避免被 overflow 裁掉） |

规则：
- 同一层级只用一档；能靠 1px `#EFE4E8` 解决的地方不加阴影。
- 阴影不叠加：不允许"卡片 shadow-2 + 内部按钮 shadow-1"。
- 移动端整体降一档（`shadow-3` → `shadow-2`，`shadow-2` → `shadow-1`），避免 OLED 上发灰发重。

### 3.4 间距栅格（4px 基准，8px 节奏）

| 值 | 用途 |
|---|---|
| 4 | 图标与文字、标签内左右、徽标内边距 |
| 8 | 控件内垂直、按钮组间距、列表项内边距 |
| 12 | 表单字段间距、紧凑卡片内边距 |
| 16 | 卡片内边距下限、浮动控件距边、区块内元素间距 |
| 24 | 卡片内边距标准、区块间距、对话框内边距 |
| 32 | 页面外边距（桌面）、面板左右、区块大间距 |
| 48 | 首屏上下留白、区块分隔（大屏） |
| 64 | 仅入口页顶部留白 |

密度原则（§9.4 保留）：**工具密、面板疏、画布空**。
- 画布页顶栏 56px 高，内边距 12/16；控件间距 8。
- 面板页外边距 32（移动端 16），卡片内边距 24，卡片间距 16。
- 表单字段间距 12（同一组）/ 24（不同组）。
- 不为"呼吸感"发明 20/28/36 这类非 4 倍数；行高与字号是例外（22/18/30/40）。

### 3.5 动效

| 场景 | 时长 | 曲线 | 只动什么 |
|---|---|---|---|
| 按钮态（hover / active / focus） | 120ms | `cubic-bezier(.2,.8,.2,1)` | `background` / `border-color` / `color` |
| 面板、抽屉、提示条出现 | 160ms | `cubic-bezier(.2,.8,.2,1)` | `opacity` + `translateY(4px)` |
| 面板、抽屉关闭 | 120ms | `cubic-bezier(.4,0,1,1)` | `opacity`（不做位移动画） |
| 对话框 | 160ms | `cubic-bezier(.2,.8,.2,1)` | `opacity` + `scale(.98→1)`，无弹跳 |
| 元素出现（画布内） | 120ms | `linear` | `opacity`（由库控制，外壳不介入） |
| 他人光标 | rAF 插值 60–80ms | 线性 | 位置（无弹簧/无甩尾） |
| Toast | 160ms 进 / 240ms 停留后淡出 | `cubic-bezier(.2,.8,.2,1)` | `opacity` |
| 骨架屏 | 1.4s 循环 | `ease-in-out` | `opacity .55 → 1`（不做 translate shimmer） |

硬约束：
- 单一过渡 ≤200ms（除 toast 停留）；不存在 >300ms 的过渡。
- 不使用 `bounce` / `elastic` / 视差 / 轮播 / 装饰粒子 / 循环闪烁横幅。
- 全局 `@media (prefers-reduced-motion: reduce)` 下：所有时长归 0，只保留状态切换，不做位移与缩放。
- 动效只用 `opacity` 与 `transform`；不动 `box-shadow`、`filter`、`backdrop-filter`、`width/height`（会触发布局或重绘）。

### 4.4 登录 / 注册页与游客认领对话框

**登录 / 注册页**

**视觉层级**
1. 表单卡片（白，浮在 `#FBF7F9` 上）。
2. 标题「登录」/「注册」。
3. 主按钮。
4. 「继续以游客身份」——次要但必须显眼到能找到（免注册是产品主张，不能登录页就把人关住）。

**布局与控件**
- 卡片：宽 400（移动端 100% − 32），`radius 20`、白底、1px `#EFE4E8`、`shadow-2`、padding 32。**不用 shadow-3**（会像营销弹窗），不加侧边插画，不做左右分栏。

**游客认领对话框（`ClaimDialog`）**

**视觉层级**
1. 标题里的数字：「把这 **2** 块临时白板转到你的账号？」（数字用 600，唯一加粗处）。

## 5. 与 Excalidraw 组件的共存

结论先行：**库是"画布"，我们是"桌面与门厅"。** 库能被变量覆写的只有"颜色与少数尺寸"，覆写不到的结构一律不硬改，而是用外壳避开。

### 5.1 主题变量能做到什么程度（`@excalidraw/excalidraw@0.18.1`，已核对随包 CSS）

变量声明位置：浅色在 `.excalidraw { … }`，深色在 `.excalidraw.theme--dark { … }`。**同权重，覆写必须保证在库 CSS 之后加载**（本项目在 `BoardCanvas` 内 `import "@excalidraw/excalidraw/index.css"`，覆写样式要么在其后 import，要么用 `.wb-canvas .excalidraw` 提高权重）。

可从随包 CSS 中确认存在、且值得覆写的变量：

| 组 | 变量 |
|---|---|
| 品牌 | `--color-primary`、`--color-primary-darker`、`--color-primary-darkest`、`--color-primary-light`、`--color-primary-light-darker`、`--color-primary-hover`、`--color-brand-hover`、`--color-brand-active`、`--color-on-primary-container`、`--color-surface-primary-container` |
| 表面 | `--color-surface-lowest`、`--color-surface-low`、`--color-surface-mid`、`--color-surface-high`、`--color-on-surface`、`--color-muted`、`--color-muted-darker`、`--color-muted-darkest`、`--color-muted-background`、`--color-disabled` |
| 描边 | `--color-border-outline`、`--color-border-outline-variant`、`--default-border-color`、`--sidebar-border-color`、`--dialog-border-color` |
| 状态 | `--color-danger`、`--color-danger-text`、`--color-danger-background`、`--color-warning`、`--color-warning-text`、`--color-warning-background`、`--color-success`、`--color-success-text` |
| 选择 | `--color-selection`、`--select-highlight-color`、`--selected` |
| 阴影/圆角 | `--shadow-island`、`--border-radius-md`、`--border-radius-lg` |
| 按钮 | `--button-bg`、`--button-border`、`--button-color`、`--button-hover-bg`、`--button-hover-border`、`--button-hover-color`、`--button-active-bg`、`--button-selected-bg`、`--button-selected-border` |
| 尺寸 | `--button-height`、`--space-factor`、`--zIndex-*` |

建议覆写值（画布内**只染色，不换风格**）：

```css

  --color-primary-light-darker: #edd2de;
  --color-primary-hover: #8e4568;
  --color-brand-hover: #8e4568;
  --color-brand-active: #743551;
  --color-on-primary-container: #ffffff;
  --color-surface-primary-container: #f4e3e9;

  --color-surface-lowest: #ffffff;
  --color-surface-low: #fbf7f9;
  --color-surface-mid: #f4eef1;
  --color-surface-high: #f4e3e9;
  --color-on-surface: #3a2e33;
  --color-muted: #6b5a61;
  --color-muted-darker: #4a3b41;
  --color-muted-darkest: #3a2e33;
  --color-disabled: #9a8a90;

  --color-border-outline: #a08d95;
  --color-border-outline-variant: #efe4e8;
  --default-border-color: #efe4e8;
  --dialog-border-color: #efe4e8;

  --color-danger-text: #9e4a4a;
  --color-danger-background: #fbeaea;
  --color-warning-text: #8a5e22;
  --color-warning-background: #fbf1e4;
  --color-success-text: #2f6b57;

  --color-selection: #a85c7c;
  --select-highlight-color: #edd2de;

```

注意：
- **深色主题需在 `.excalidraw.theme--dark` 重复声明**，否则切主题后变量被库的深色块覆盖。v1 只做浅色，`theme` 固定 `"light"`。
- `--color-selection` 改成主色后，元素选中框与外框手柄会偏玫瑰色。这是"我们的 UI 色"，可以改；但**必须**对照深色元素与粗描边元素检查是否被误认成元素本身（截图验收项）。
- `--color-gray-*` 不要整套替换：它被数十条库内规则引用，改一两个值会得到"半新半旧"的灰，比不改更难看。要中性灰时改 `--color-surface-*` 与 `--color-muted*` 这一层。
- `--button-height` / `--space-factor` 只微调，**不改库的密度**（改多了工具条会错位）。

### 5.2 库不开放、必须靠外壳解决的部分

| 不开放项 | 事实 | 外壳对策 |
|---|---|---|
| 元素默认描边色板（5 色） | 色板在 JS 常量里，`UIOptions` 无法替换调色板内容 | 不试图替换。只通过 `appState.currentItemStrokeColor` 设初始色（建议 `#5A2A3F`）；接受用户点开看到库默认色板 |
| 画布图形 12 色板（§9.1 曾提出） | 同理，属代码常量 | **本文明确放弃**（附录 B-4）：不宣称"自定义画布色板" |
| 文本字体族（Virgil / Helvetica / Cascadia / Nunito / 中文字体） | 字体清单与字体文件在库内 | 不覆写。中文字符由系统字体渲染，中文文本元素天然是系统无衬线；不在外壳 CSS 里给 `.excalidraw` 设 `font-family`（会连带改掉 UI 文字） |
| 工具栏 / 属性面板 / 菜单的内部结构与图标 | 只有少量插槽（`renderTopRightUI`、`renderFooter`、`UIOptions.canvasActions`、隐藏工具等），没有"替换工具条"的公开 API | **不自研第二套工具条**。靠变量 + 少量 CSS 微调（圆角、阴影、间距）；移动端位置调整依赖类名，属"锁版本 + 截图验收"的脆弱点，升级必须重跑 |
| 画布背景 | 由 `appState.viewBackgroundColor` 控制 | 固定 `#FFFFFF`；网格默认关 |
| 元素圆角、命中检测、手势、光标渲染 | 库内实现 | 不干预 |
| 库的弹窗/命令面板文案与排版 | 库内 i18n 与样式 | 接受；外壳弹窗（分享、认领、登录）自己写，不复用库弹窗 |

### 5.3 分工表（谁负责什么）

| 区域 | 归属 | 规则 |
|---|---|---|
| 页面底、卡片、列表、表单 | 自研（§1–§3 token） | 可自由使用主色、圆角、阴影 |
| 画布页顶栏、`SaveToAccountBanner`、断线横幅、底部状态条 | 自研 | **独立成条，压在画布上方**，不浮动在画布之上 |
| 分享面板、成员弹层、认领对话框、登录页、toast | 自研 | 覆盖层，`radius 20` / `shadow-3` |
| 画布视口 | 库 | `#FFFFFF`，中性 |
| 库的工具条、属性面板、右键菜单、命令面板 | 库 | 只做变量染色 + 必要 CSS 微调，不换结构 |
| 元素、文本、光标、选中框 | 库 | 只有 `--color-selection` 一个变量属于我们 |

**"外壳自研 + 画布内保持中性"的具体含义（三条可执行规则）**
1. **画布内不出现主色装饰。** 主色只出现在选中框（UI 反馈）与顶栏/抽屉（外壳）。不把画布底色染粉、不给画布加玫瑰描边、不在画布上叠品牌水印。
2. **画布外不使用库的视觉语言。** 我们的按钮是 10px 圆角 + 平面色，库的按钮是它的 6px/8px 体系；两者不相邻摆放（顶栏与库浮动工具条之间至少留 12px 或一条 `#EFE4E8` 分隔）。
3. **同名同义。** 库的"primary"和我们的"primary"指向同一个 `#A85C7C`，避免出现"两种紫/两种玫瑰"；库的其余配色（灰、红）只在画布内生效，外壳不借用。

### 5.4 落地与验收

- 变量覆写写成独立样式层（建议 `apps/web/src/styles/excalidraw-theme.css`），**只允许** 声明变量与极少量尺寸微调；`!important` 与深层类名选择器出现时必须在注释里写明原因。
- 每次升级 `@excalidraw/excalidraw` 必须跑一次视觉回归：入口页 → 画布 → 工具条展开 → 属性面板 → 分享抽屉 → 只读模式，各截一张 1280×800 与 390×844。
- 建议加一个启动冒烟检查（后续里程碑，不在本轮）：`getComputedStyle` 读 `--color-primary` 是否为 `#a85c7c`。CSS 变量名变更不会报错，只会静默失效，这是最容易漏的回归。

## 6. 风险与取舍

### 6.1 会让它看起来像模板的做法（明确避免）

| 模板特征 | 为什么廉价 | 本方案的做法 |
|---|---|---|
| 居中 hero：大标题 + 两按钮 + 居中副文案 | 与 90% 的 SaaS 落地页同构 | 左对齐单列、只有一个主按钮、副文案在按钮下方 |
| 三栏"图标 + 标题 + 说明"特性区 | 图标凑数，无信息 | 三行纯文字能力点，或干脆不放 |
| 卡片网格 + 缩略图 + 彩色徽标堆叠 | 后台模板的标配 | 缩略图只是 72px 色块占位；卡片只有标题、时间、一个徽标 |
| 毛玻璃 + 渐变光斑 + 悬浮圆角巨卡 | 2021 年后的"AI 生成感" | 纯色底 + 一层极淡径向渐变；遮罩与抽屉全部不透明 |
| 24px 全圆角 + 弹跳动效 + emoji | 幼态，削弱工具属性 | 圆角上限 20，无弹跳，不用 emoji 做图标 |
| 紫色/蓝色渐变作为品牌色 | 与主色冲突且通用 | 主色只有干玫瑰一种，语义色只做状态 |
| 大量线性图标 + 统一描边 + 圆底 | 图标墙 | 图标只在必要处出现（返回、复制、锁、关闭），其余用文字 |

补充：**排印与留白承担个性**，不靠装饰承担。板名、时间、真实数据出现在界面上，本身就是"不像模板"的证据。

### 6.2 会拖性能的做法

| 做法 | 代价 | 约束 |
|---|---|---|
| `backdrop-filter`（毛玻璃） | 每次滚动/重绘触发 GPU 合成 pass，移动端掉帧明显；且对比不可控 | **全局禁用**。需要"浮起感"用不透明底 + `shadow-3` |
| 多层阴影叠加 | 大面积模糊半径的绘制成本随面积线性增长 | 同屏最多 1 个 `shadow-3`；列表卡片默认 `shadow-0` |
| 大图/纹理背景 | 首屏多一次解码与显存占用；DPR 2 下更贵 | 不用背景图；渐变用 CSS `radial-gradient` 单层 |
| 列表缩略图（真实画布截图） | 每卡一次 canvas 渲染或一次图片请求 | v1 用色块占位；缩略图延后，且必须服务端生成、固定 2 倍图以内 |
| 自托管中文字体 | 全量中文字体 3–8MB | 只允许拉丁 Inter/Fraunces + 标题用极小中文子集；加载失败静默降级 |
| 动画 `box-shadow` / `width` / `filter` | 触发布局或重绘 | 只动 `opacity` + `transform`；阴影切换用 `box-shadow` 的瞬时状态（无过渡）即可 |
| 骨架屏 shimmer（translateX 扫光） | 大面积合成层持续重绘 | 用 `opacity` pulse，1.4s，不用扫光 |
| 光标高频广播 + CSS 过渡 | 双倍开销 | rAF 直写 `transform`，60–80ms 插值 |

关于画布内的性能：库的渲染开销由元素数与 DPR 决定，外壳的控制点只有"不要给画布容器加 `filter` / `opacity` / `transform`"（会迫使整块画布离屏合成），以及不要在画布上叠大面积半透明遮罩。

### 6.3 移动端砍掉的效果

| 效果 | 移动端处理 |
|---|---|
| `backdrop-filter` | 全部禁用（本方案桌面也不用） |
| 卡片 hover 阴影 | 无 hover，改为 `:active` 时 `#F4EEF1` 底（颜色反馈，不动阴影） |
| 多层阴影 | 降一档：`shadow-3` → `shadow-2`，`shadow-2` → `shadow-1` |
| 衬线展示标题 | 关闭 `--font-display`，标题用无衬线 600（宋体在手机上更糊） |
| 顶部径向渐变 | 保留但半径减半、透明度降到 .35（省一次大半径渐变光栅） |
| 底部状态条 | 隐藏（元素数/缩放比并入工具条） |
| 2 列卡片 | 改单列 |
| 分享抽屉 | 改底部抽屉，≤80vh，`radius 20`，把手 32×4 |
| 视差/大图/装饰动画 | 本就不做 |

保留项：触控目标 ≥44×44、正文 14px 不缩、圆角与配色一致、只读徽标一致。

### 6.4 可访问性与实现风险

1. **主按钮对比余量只有 0.18**（4.68:1）。任何"给按钮加浅色描边、给文字加透明度、换更浅的主色"都会掉到 AA 以下。这条必须写进 review checklist。
2. **`#9A8A90` 极易被误用作时间戳/说明**。建议只在 placeholder 与 `disabled` 两处出现，且代码里以 `--text-disabled` 命名，不用 `--text-weak` 这种模糊名字。
3. **中文 500 字重在 Windows 上是合成的**，跨平台截图会看到粗细不一致。验收以 Windows Chrome 为准，不要只在自己的 mac 上看。
4. **库的类名与 CSS 变量没有 API 稳定性承诺**。锁版本 + 视觉回归是唯一防线；不要写深层选择器去改工具条结构。
5. **焦点环必须可见**。`outline: none` 一律禁止；用 `shadow-focus` 时注意容器 `overflow: hidden` 会裁掉外环。
6. **只读与游客是两种状态，不能合并表达**。只读是权限（黄色徽标 + 锁），游客是身份（灰玫瑰徽标），同屏出现时只读优先显示，游客信息放头像菜单。

### 6.5 待评审确认项

1. 是否接受**自托管 Inter**（约 30KB，拉丁）+ 可选 Fraunces（约 28KB）。若要求"零字体请求"，`--font-display` 直接降级为无衬线 600，其余不变。
2. **主按钮 hover 方向**：本方案改为"变深"（`600 → 700`）。这与 §9.1 表格"500 用于 hover"的写法冲突，但 500 + 白字只有 3.15:1。需确认以本方案为准。
